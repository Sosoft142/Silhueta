# Silhueta

- A versão pública do aplicativo tem como fonte `APP_VERSION` em `index.html`. O `VERSION=7` é a versão dos dados salvos e não deve ser alterado para uma atualização visual.
- Em cada atualização do aplicativo, execute `node scripts/release.mjs patch` (ou informe uma versão X.Y.Z maior). O comando atualiza a versão pública, o cache do service worker e o README juntos.
- A URL do manifest deve permanecer `./manifest.webmanifest`, sem query de versão. O `id` deve permanecer `/Silhueta/index.html`, preservando a identidade calculada para as instalações antigas. Não renomeie o manifest nem altere `id`, `start_url` ou `scope` para contornar um erro de instalação.
- O manifest usa atualização pela rede com fallback offline. A limpeza de caches do service worker deve se limitar ao prefixo do Silhueta e preservar dados locais e caches de outros projetos.
- O rodapé de Configurações deve sempre mostrar `APP_VERSION`, sem manter outra cópia do número. Execute `node scripts/release.mjs --check` antes de publicar.
- A logo interna usa `icons/brand-mark.svg`, com fundo transparente e os mesmos traços da silhueta aprovada. Os ícones de instalação, o favicon e os arquivos referenciados pelo manifest são separados: só os altere mediante solicitação explícita.
- Preserve os registros existentes, a compatibilidade dos backups e as 12 ilustrações anatômicas aprovadas.
- `silhueta.ui.quickMetric` guarda apenas a última região, por aparelho. `silhueta.ui.lastSyncConfirmation` só pode ser atualizado depois da verificação bem-sucedida do Gist; não use datas importadas/sincronizadas para afirmar que este aparelho confirmou a nuvem.
- Desfazer uma exclusão conserva o ID e os dados da medição, com relógio de sincronização posterior ao marcador excluído. Recuse a restauração se o registro tiver sido alterado novamente; não substitua uma versão mais recente.
- A referência no registro rápido usa a última medição real pela data, excluindo registros removidos, e não preenche o novo valor. A confirmação detalhada só pode afirmar salvamento local quando `storageOK` for verdadeiro.
- `preferences.measurementWeekday` aceita somente null ou um inteiro de 0 (domingo) a 6 (sábado). A contagem semanal segue o calendário local do aparelho, com zero no próprio dia; salvar uma região não conclui o dia inteiro. A atualização do contador não deve redesenhar nem apagar formulários em edição.
- O cache HTML tem uma única entrada canônica em `index.html`; a raiz e as consultas ao documento devem funcionar offline usando essa mesma cópia. Reutilize os formatadores por precisão e a lista já consultada em cada cartão do painel.
- O lembrete do Google Agenda abre somente um modelo de evento semanal, usando o dia salvo, a próxima ocorrência futura e o fuso do aparelho. Não afirme que o evento foi salvo ou que notificações estão ativas. `silhueta.ui.measurementReminderTime` é uma preferência local; não inclua medidas, notas, credenciais ou consultas da URL do app no link externo. Eventos já criados são alterados ou excluídos na própria agenda.
- Medidas separa Registrar e Histórico sem recriar os formulários ao alternar. Preserve os rascunhos dos dois modos; os atalhos de registro e a edição devem abrir Registrar. O histórico e a lista de Evolução exibem no máximo dez registros por página, agrupados pela data real, incluindo os antigos sem data. Filtrar retorna à primeira página; exclusões ajustam uma página que deixou de existir. Observações abertas devem continuar associadas ao ID do registro.
- A nuvem do cabeçalho não tem texto visível: cinza para desconectado, verificação pendente ou envio aguardando; verde fixo somente após confirmação; verde pulsante durante a sincronização; vermelho para falhas, inclusive de armazenamento. Mantenha a descrição acessível e o alvo de 44 px, respeite movimentos reduzidos e não limpe erro, espera ou progresso ao abrir o diálogo.
- Início compacta apenas o cabeçalho com dados e o lembrete; os cartões de medidas e as demais abas preservam a apresentação. Personalizar abre um painel junto aos indicadores, mantém a abertura ao escolher ou ordenar regiões e conserva o foco por ID na seleção. O contador acompanha o histórico com singular/plural. O histórico recente conserva as cinco últimas medições reais, agrupadas pela data, incluindo o rótulo dos registros antigos sem data; cada linha edita seu ID original e o link para Evolução fica no rodapé.

- `navigation.js` coordena History API e as camadas de menu, sincronização e edição. O histórico recebe somente opções de tela, IDs e rolagem; nunca dados de formulário, token ou registros completos. A raiz não ganha uma entrada artificial. Descarte recusado restaura a posição no histórico sem recriar o DOM; fechamento explícito consome a entrada e operações pendentes não podem fechar uma janela nova. Não acrescente um CloseWatcher independente aos overlays personalizados. Preserve os testes de voltar/avançar, recarga, rascunhos e saída normal.
- A limpeza de CSS deve preservar ordem, especificidade e condições responsivas. `qa/navigation-visual-audit.mjs` isola a limpeza dos ajustes solicitados e compara estilos calculados/geometria com o CSS 2.9.18, além de testar 320, 360, 390 e 1440 px. Mantenha o módulo de navegação na lista CORE do service worker.
- Formulários expansíveis de metas e agenda têm etapa própria no histórico. Fechar uma seção preserva seu DOM e os rascunhos; sair da tela continua exigindo descarte confirmado. Salvar metas consome a etapa sem apagar outro formulário. Se um select nativo cortar seu valor, mostre o texto completo somente nesse caso, sem duplicar a leitura assistiva.
